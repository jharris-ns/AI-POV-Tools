# Netskope AI Services — Combined Stack Deployment

This folder provides a Terraform template that deploys the **Netskope AI Gateway (AIG)**, **AI Guardrails LLM service**, and **DLP On-Demand (DLPoD)** together in a single `terraform apply`. All three services are automatically wired together — no manual registration steps required.

Use this template when you want to stand up the full AI inspection stack in one shot for a POV or lab environment. If you only need one or two components, see [deploying components separately](#deploying-components-separately).

---

## What is this stack?

Netskope's AI inspection stack sits between AI clients (ChatGPT, Copilot, etc.) and the internet. It acts as an SSL-intercepting proxy that applies three layers of control:

| Layer | Component | What it does |
|-------|-----------|--------------|
| 1 | **AI Gateway (AIG)** | SSL termination, policy enforcement, traffic routing |
| 2 | **AI Guardrails** | GPU-accelerated LLM inference — scans prompts and responses against Netskope AI policies |
| 3 | **DLP On-Demand (DLPoD)** | AI-aware DLP — detects sensitive data in AI queries and responses |

Traffic flow: `Client → AIG (port 443) → Guardrails (port 8080)` for LLM inspection, and `AIG → DLPoD (port 443)` for DLP inspection. The AIG makes both connections in parallel for each AI transaction.

## What this deploys

```
Internet
    │ (port 443)
    ▼
Internet Gateway
    │
    ▼
Public subnet (10.0.1.0/24)
  ├── AI Gateway EC2 (Elastic IP) ─────────────────────► Netskope Cloud
  └── NAT Gateway ────────────────────────────────────► repos, Docker Hub, S3, licensing
         │
         ▼
Private subnet (10.0.2.0/24)
  ├── Guardrails GPU EC2 (.10) — LLM content inspection
  └── DLPoD EC2 (.20)          — DLP inspection (TLS, port 443)
```

### EC2 instances

| Instance | Default type | vCPU | RAM | Purpose |
|----------|-------------|------|-----|---------|
| AI Gateway | `c6a.4xlarge` | 16 | 32 GB | SSL offload, proxying, policy enforcement |
| Guardrails | `g4dn.xlarge` | 4 | 16 GB | NVIDIA T4 GPU — LLM model inference |
| DLPoD | `c5d.4xlarge` | 16 | 32 GB | CPU-bound DLP content scanning. Local NVMe speeds up first-boot initialization |
| Bastion | `t3.small` | 2 | 2 GB | SSH/SSM troubleshooting access — **delete post-POV** |

### AWS resources created

| Service | Resources |
|---------|-----------|
| **VPC** | VPC, public + private subnets, internet gateway, NAT gateway, route tables |
| **EC2** | 4 instances (AIG, Guardrails, DLPoD, Bastion), 2 Elastic IPs (AIG + NAT GW) |
| **Security groups** | One per instance with least-privilege ingress/egress rules |
| **IAM** | Instance roles and profiles for AIG and Guardrails (DLPoD uses user-data only) |
| **Secrets Manager** | AIG bootstrap secret (enrollment token + Guardrails host + DLPoD TLS config) |
| **SSM Parameter Store** | Guardrails readiness signal (`/<prefix>/guardrails-ready`) |
| **CloudWatch Logs** | Guardrails service log group (30-day retention) |
| **VPC Endpoints** | Interface: SSM, SSMMessages, EC2Messages, CloudWatch Logs. Gateway: S3 |
| **Route 53** | Private hosted zone resolving `dlp.aigw.internal` → DLPoD private IP |
| **TLS certificates** | CA + leaf cert for DLPoD (generated by Terraform `tls` provider — no external CA needed) |

## How long does deployment take?

`terraform apply` blocks at two readiness gates before creating the AIG. Total observed time on `g4dn.xlarge` in us-west-1:

| Stage | Duration | What's happening |
|-------|----------|-----------------|
| VPC + networking | ~2 min | Subnets, IGW, NAT gateway, route tables, VPC endpoints |
| Guardrails Phase 1 | ~15 min | OS updates, NVIDIA GPU driver install, reboot |
| Guardrails Phase 2 | ~15–20 min | Docker, NVIDIA container toolkit, 15 GB S3 image download (~130 MiB/s), `docker load`, health check |
| DLPoD bootstrap | ~5–10 min | `nsbootstrap` applies TLS certs and license, `nssetupdlpaas` installs the DLP pod |
| AIG creation | ~2–3 min | Enrollment token written to Secrets Manager, AIG EC2 boots and self-enrolls |
| **Total** | **~35–50 min** | |

The longest variable is Guardrails Phase 2 — `docker load` of a 15 GB image takes 3–5 minutes and cannot be parallelized.

## Prerequisites

| Requirement | How to get it |
|-------------|---------------|
| **Terraform ≥ 1.5** | [Download](https://developer.hashicorp.com/terraform/install) or `brew install terraform` |
| **AWS credentials** | `aws configure`, AWS SSO, or environment variables |
| **GPU instance quota** | EC2 service quota for `g4dn` or `g5` in your target region — AWS console → Service Quotas → EC2 |
| **Netskope REST API v2 token** | Netskope tenant → Settings → Tools → REST API v2 → Generate token (AIG scope) |
| **AIG AMI ID** | Subscribe to the Netskope AI Gateway on AWS Marketplace — AMI ID is region-specific and shown after accepting terms |
| **DLPoD AMI ID** | Obtained from Netskope — region-specific. Default in `terraform.tfvars.example` is for us-west-1 |
| **DLPoD license key** | Obtained from Netskope |
| **S3 bucket with Guardrails image** | Upload `aisecurity-llm.tgz` to an S3 bucket in the same region before running `terraform apply` |

Set Netskope credentials as environment variables — never put them in a tfvars file:

```bash
export NETSKOPE_SERVER_URL="https://mycompany.goskope.com/api/v2"
export NETSKOPE_API_KEY="your-v2-token"
```

## Upload the Guardrails image to S3

The Guardrails GPU instance downloads the Docker image from S3 at first boot. Upload it before running `terraform apply`.

```bash
aws s3 mb s3://my-guardrails-bucket --region YOUR_REGION
aws s3 cp aisecurity-llm.tgz s3://my-guardrails-bucket/aisecurity-llm.tgz
```

## How the services are wired together

Terraform writes a Secrets Manager bootstrap secret containing the AIG enrollment token, the Guardrails host, and the DLPoD TLS configuration:

```json
{
  "bootstrap": true,
  "enrollment_token": "<generated-by-terraform>",
  "ai_guardrails": {
    "host": "http://10.0.2.10:8080/invocations"
  },
  "dlp": {
    "host": "https://dlp.aigw.internal",
    "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n"
  }
}
```

The AIG reads this secret at first boot and configures both services during enrollment. A Route 53 private hosted zone resolves `dlp.aigw.internal` to the DLPoD private IP within the VPC.

**DLPoD TLS:** Terraform generates a two-tier certificate hierarchy (CA + leaf) and delivers it to DLPoD via EC2 user-data. The CA certificate is embedded in the AIG bootstrap secret so the AIG can verify DLPoD's TLS chain without a public CA.

Both private IPs are pinned in `terraform.tfvars` (`guardrails_private_ip`, `dlpod_private_ip`) so the bootstrap secret can reference them before the instances are created.
