# DLP On-Demand — Existing VPC Deployment

Deploys a Netskope DLP On-Demand (DLPoD) appliance into an existing AWS VPC with a single `terraform apply`. DLPoD is zero-touch provisioned — Terraform generates TLS certificates and delivers the full bootstrap config via EC2 user-data. No manual console steps are required.

Use this template as **Stage 2** of a staged build where you deploy Guardrails, DLPoD, and the AIG separately. See [staged build workflow](../../ai-services-all/README.md#staged-build-deploying-components-in-order).

---

## What this deploys

| Resource | Details |
|----------|---------|
| **EC2 instance** | DLPoD appliance (`c5d.4xlarge` default) with pinned private IP and high-IOPS root volume |
| **TLS certificates** | CA + leaf cert generated by Terraform `tls` provider — no external CA required |
| **Security group** | Port 443 restricted to `allowed_inspection_cidr`; port 22 disabled by default |
| **IAM role** | Minimal instance profile (DLPoD reads bootstrap from user-data, no AWS API calls needed) |
| **Route 53 private hosted zone** | Resolves `dlpod_hostname` → `dlpod_private_ip` within the VPC |

The Route 53 zone is required because the AIG connects to DLPoD via hostname (`https://dlp.aigw.internal`), not bare IP. Go's TLS stack verifies the hostname against the cert's DNS SANs — a bare-IP URL causes verification to fail even with a valid IP SAN.

## Prerequisites

| Requirement | Notes |
|-------------|-------|
| **Terraform ≥ 1.5** | `brew install terraform` or [download](https://developer.hashicorp.com/terraform/install) |
| **AWS credentials** | `aws configure`, AWS SSO, or environment variables |
| **Existing VPC** | With a subnet that has outbound internet access for bootstrap |
| **DLPoD AMI ID** | Region-specific — obtain from Netskope. Default in `terraform.tfvars.example` is us-west-1 |
| **DLPoD license key** | Obtain from Netskope |

## Quick start

```bash
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — required: vpc_id, subnet_id, vpc_cidr,
#   allowed_inspection_cidr, dlpod_private_ip, dlpod_licensekey

terraform init
terraform apply
```

Bootstrap completes in **5–10 minutes** after the instance launches. There is no Terraform readiness gate in this template — monitor progress directly:

```bash
# DLPoD does not support SSM Session Manager. Connect via SSH from a bastion:
ssh -i your-key.pem nsadmin@<dlpod_private_ip>
sudo journalctl -u nsbootstrap -f
```

## Outputs — what to pass to the AIG template

After `terraform apply`, retrieve the values the AIG template needs:

```bash
terraform output dlp_host        # e.g. https://dlp.aigw.internal
terraform output -raw ca_cert_pem  # CA cert PEM — pass as dlp_ca_cert_pem to AIG template
```

These map to AIG `aig/existing-vpc/` variables:

| DLPoD output | AIG variable |
|-------------|-------------|
| `dlp_host` | `dlp_host` |
| `ca_cert_pem` | `dlp_ca_cert_pem` |

---

## Key variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `vpc_id` | Yes | — | Existing VPC ID |
| `subnet_id` | Yes | — | Subnet for DLPoD instance — must have outbound internet access |
| `vpc_cidr` | Yes | — | VPC CIDR block (used to compute VPC DNS resolver address) |
| `allowed_inspection_cidr` | Yes | — | CIDR that can reach port 443 — set to AIG subnet CIDR |
| `dlpod_ami_id` | No* | `ami-0b3a14615c7e7944e` | DLPoD AMI — default is us-west-1, update for other regions |
| `dlpod_private_ip` | Yes | — | Static IP within the subnet CIDR — embedded in TLS cert SAN |
| `dlpod_licensekey` | Yes | — | Netskope license key |
| `dlpod_hostname` | No | `dlp.aigw.internal` | TLS hostname and Route 53 record name |
| `dlpod_instance_type` | No | `c5d.4xlarge` | Instance type — local NVMe recommended for fast bootstrap |

> **\* `dlpod_ami_id`** has a default but it is region-specific. The default is only valid in us-west-1.

> **`dlpod_private_ip`** is embedded in the TLS certificate SAN and the Route 53 A record. Changing it after `terraform apply` requires replacing the instance.

## Outputs

| Output | Description |
|--------|-------------|
| `instance_id` | EC2 instance ID |
| `private_ip` | Assigned private IP |
| `dlp_host` | DLP host URL for the AIG bootstrap secret (`https://<dlpod_hostname>`) |
| `ca_cert_pem` | CA certificate PEM — pass to AIG as `dlp_ca_cert_pem` |
| `security_group_id` | DLPoD SG — optionally tighten ingress after AIG is deployed |
| `route53_zone_id` | Private hosted zone ID — associate additional VPCs if AIG is in a different VPC |

## Staged build workflow

This template is designed to be used as part of a staged build:

```
Stage 1: gpu-guardrails/existing-vpc/   →  outputs: ai_guardrails_host
Stage 2: dlpod/existing-vpc/            →  outputs: dlp_host, ca_cert_pem
Stage 3: aig/existing-vpc/              →  inputs:  guardrails_host, dlp_host, dlp_ca_cert_pem
```

See [ai-services-all/README.md](../../ai-services-all/README.md#staged-build-deploying-components-in-order) for the full workflow.

## Post-deployment: tighten security group

The DLPoD SG ingress uses a CIDR rule because the AIG security group ID is unknown at deploy time. After the AIG is deployed you can optionally replace the CIDR rule with an SG reference:

```bash
# Get the AIG SG ID from aig/existing-vpc/ outputs
AIG_SG=$(cd ../../aig/existing-vpc && terraform output -raw security_group_id)
DLPOD_SG=$(terraform output -raw security_group_id)

# Add SG-based rule
aws ec2 authorize-security-group-ingress \
  --group-id "$DLPOD_SG" \
  --protocol tcp --port 443 \
  --source-group "$AIG_SG" \
  --region YOUR_REGION

# Remove the broad CIDR rule
aws ec2 revoke-security-group-ingress \
  --group-id "$DLPOD_SG" \
  --protocol tcp --port 443 \
  --cidr YOUR_INSPECTION_CIDR \
  --region YOUR_REGION
```
